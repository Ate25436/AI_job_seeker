# AI就活生 ~面接担当者を鍛えるAIトレーニング~

## 背景
- 企業において，新卒採用でどういった人材を採るかは今後の企業の発展につながる重要なイベント
- 新卒採用が担当できるようになるためには，現場での経験を積み，新卒者の見極めができるようになることが肝要
- しかし，まだ習熟しきっていない新卒採用担当者が面接を担当した場合，新卒者の思いを汲み取ることができず，望まない就職になってしまう可能性がある
## 目的
- 面接官を育成するためのに，採用力の底上げにつながるようなゲームを作ろう

## MVP仕様

### 1プレイの基本フロー
- 1プレイは `開始 -> 10分質問 -> 採点 -> 結果表示` の4段階で進行する
- 開始時に就活生シナリオを1件だけ読み込み，そのプレイ中は固定する
- 質問時間は10分とし，時間切れになったら新しい質問は送れないようにする
- 制限時間終了後は，ユーザーに社会人基礎力12項目の採点を入力させる
- 採点完了後に，成績，正解とのズレ，フィードバックを結果画面に表示する

### シナリオ数
- MVPでは，1プレイにつき就活生シナリオは1人分のみ扱う
- 初期実装では，まず固定シナリオ1件で動作確認する
- その後，シナリオ生成または複数シナリオのランダム出題に拡張する

### 結果画面に表示する内容
- 総合成績
- 偏差値換算したスコア
- 12項目それぞれの「ユーザー採点」と「正解スコア」
- 各項目の差分
- 3分類ごとの傾向まとめ
- 良かった点
- 見抜けなかった点
- 次回に向けた質問改善案

### 成績表示の形式
- ユーザーへの主表示は100点満点換算の総合成績と偏差値の2本立てにする
- 総合成績は「正解とのズレが小さいほど高得点」とする
- 偏差値は将来的にプレイデータ全体から補正する前提とし，MVPでは暫定式で50中心に正規化する
- 結果画面では数値だけでなく，`S / A / B / C` のランクも補助的に表示する

### フィードバックの粒度
- フィードバックは「総評」「項目別コメント」「次に聞くべき質問例」の3段階で返す
- 総評では，今回の面接で見抜けた強みと見抜けなかった傾向を短くまとめる
- 項目別コメントでは，差分が大きかった項目だけを優先して表示する
- 質問例では，次回同様の候補者を見極めるための深掘り質問を1項目につき1から2個提示する
- MVPではまずルールベースで実装し，必要に応じて自然文生成へ拡張する

## 評価項目・採点ルール仕様

### 評価項目のデータ構造
- 社会人基礎力は3カテゴリ12項目で管理する
- システム上は各項目を以下の属性で保持する
  - `category_id`: `action` / `thinking` / `teamwork`
  - `category_label`: `前に踏み出す力` / `考え抜く力` / `チームで働く力`
  - `competency_id`: 英字の一意キー
  - `competency_label`: 項目名
  - `score`: 1から5の整数
  - `evidence_summary`: 根拠の要約
  - `evidence_episode`: 根拠となる具体的エピソード
  - `signal_strength`: `strong` / `medium` / `weak`
  - `question_tags`: その項目を見極めやすい質問カテゴリ一覧
- 初期実装では以下の12項目を固定で使う

| category_id | category_label | competency_id | competency_label |
| --- | --- | --- | --- |
| action | 前に踏み出す力 | initiative | 主体性 |
| action | 前に踏み出す力 | influence | 働きかけ力 |
| action | 前に踏み出す力 | execution | 実行力 |
| thinking | 考え抜く力 | issue_finding | 課題発見力 |
| thinking | 考え抜く力 | planning | 計画力 |
| thinking | 考え抜く力 | creativity | 創造力 |
| teamwork | チームで働く力 | communication | 発信力 |
| teamwork | チームで働く力 | listening | 傾聴力 |
| teamwork | チームで働く力 | flexibility | 柔軟性 |
| teamwork | チームで働く力 | situational_awareness | 状況把握力 |
| teamwork | チームで働く力 | discipline | 規律性 |
| teamwork | チームで働く力 | stress_control | ストレスコントロール |

### `high / middle / low` の割り当て仕様
- 1シナリオごとに `action` / `thinking` / `teamwork` へ `high` / `middle` / `low` を1つずつ重複なしで割り当てる
- 初期の固定シナリオでは `action = high`、`thinking = low`、`teamwork = middle` を採用する
- 将来的なランダム生成では，3カテゴリへの割り当て順を毎回シャッフルして決める
- カテゴリ単位の傾向は，そのカテゴリに属する各項目の点数分布へ反映する

### 点数生成ルール
- 各評価項目の点数は1から5の整数とする
- `high` カテゴリ内の項目は4か5のみを許容する
- `low` カテゴリ内の項目は1か2のみを許容する
- `middle` カテゴリ内の項目は3を中心とし，必要に応じて2または4も許容する
- `middle` カテゴリでは3項目以上ある場合，少なくとも過半数を3にする
- 1カテゴリ内の全項目が同点になるのは避け，1点分のばらつきを持たせる
- 12項目全体を見たときに，スコアの高低差が視認しやすい分布にする

### 根拠文のフォーマット
- 各項目に対して，点数だけでなく面接で推測可能な根拠文を保持する
- 根拠文は以下の3層で管理する
  - `evidence_summary`: 面接官向けの短い要約
  - `evidence_episode`: 行動，状況，本人の判断，結果まで含む具体文
  - `observable_signals`: 面接中に出やすい言い回しや行動特徴
- `evidence_episode` は次の型に沿って作る
  - `状況 -> 本人の行動 -> 結果 -> 評価につながる解釈`
- 例
  - 主体性が高い場合: `学園祭の出店準備で役割が曖昧だったため，自ら企画案と担当表を作成し，メンバーへ提案して準備を前進させた。その結果，準備の遅れが解消され，主体的に周囲を動かす力が見られた。`
  - 課題発見力が低い場合: `作業参加者が集まらない状況で，忙しさや情報共有不足といった原因を切り分けられず，対策が場当たり的になった。そのため，問題の本質を見抜く力は弱めと評価する。`

### 回答と評価項目の対応方針
- 1つの回答は複数項目の根拠になってよい
- ただし，各項目には「主に見える質問カテゴリ」をあらかじめ定義する
- 初期方針は以下の通りとする

| competency_id | 主に見える質問カテゴリ |
| --- | --- |
| initiative | ガクチカ, 自己PR |
| influence | チームワーク, ガクチカ |
| execution | ガクチカ, 仕事観・価値観・将来像 |
| issue_finding | ガクチカ, エンジニア向けの質問 |
| planning | ガクチカ, チームワーク |
| creativity | ガクチカ, エンジニア向けの質問 |
| communication | チームワーク, 志望動機 |
| listening | チームワーク, ストレス耐性 |
| flexibility | チームワーク, ストレス耐性 |
| situational_awareness | チームワーク, ガクチカ |
| discipline | 自己PR, 仕事観・価値観・将来像 |
| stress_control | ストレス耐性, 自己PR |

### 採点時の運用ルール
- 面接官候補生は12項目すべてを1から5で採点する
- 採点時には項目名のみを表示し，正解カテゴリの `high / middle / low` は見せない
- フィードバックでは，各項目の差分だけでなく，カテゴリ単位でもずれを集計する
- まずは全項目を同一重みで扱い，将来的に重要度重み付けを検討する
## アプローチ
- あらかじめ，評価項目とそのスコアを決める
  - このとき，スコアの大小がはっきりわかるようにする
    - 項目A: 3, 項目B: 4, 項目C: 3 よりも，項目A: 1，項目B: 5，項目C:4 みたいになるようにする
- その評価項目になるように就活生の情報を作る
  - ガクチカ，志望動機など
- ユーザー（面接官候補生）がAIに質問する
  - このとき，AIはRAGベースのエージェントで基本的には上記の情報に従って答える
- 質問の返答を元にユーザーが評価項目にスコアをつける
- スコアのズレをユーザーに伝え，可能ならフィードバックも作る

## 詳細な動き

### 準備

- 評価項目は社会人基礎力チェックシートを用いる
  - 前に踏み出す力
    - 主体性
    - 働きかけ力
    - 実行力
  - 考え抜く力
    - 課題発見力
    - 計画力
    - 創造力
  - チームで働く力
    - 発信力
    - 傾聴力
    - 柔軟性
    - 状況把握力
    - 規律性
    - ストレスコントロール
- スコアの決定では，最初に「前に踏み出す力」，「考え抜く力」，「チームで働く力」のそれぞれに high, middle, low を割り当てる（重複不可）
  - 試験的に，はじめの方は「前に踏み出す力」がhigh，「考え抜く力」がlow，「チームで働く力」がmiddleになるように設定する
- high の項目は4か5，low は1か2，middle は3が最も多くなりその他は2か4になるようにランダムな整数でスコアを割り当てる
- そのスコアになった理由を少し具体的な根拠とともに生成する
  - 例1: 主体性は5，理由はサークルで学園祭に出し物をすることになったときに出店担当として積極的に企画したから
  - 例2: 課題発見力は1，理由は学園祭の準備を手伝ってくれる学生があまりおらず，なぜそうなったのかの課題を特定できなかったから

- 以下の質問に答えられるようにRAG用のデータを作る
  - ガクチカ
    - 学生時代に最も力を入れて取り組んだことは何ですか？
    - なぜその活動に取り組もうと思ったのですか？
    - その取り組みの中で、最も困難だったことは何ですか？また、それをどのように乗り越えましたか？
    - その活動の目標はどのように設定しましたか？
    - 目標を達成するために、ご自身で工夫した点があれば教えてください。
    - その経験における、あなた自身の最大の成功体験は何でしたか？
    - その経験における、最も大きな失敗や反省点は何ですか？
    - その経験を通じて何を学び、どのような成長がありましたか？
  - チームワーク
    - チームで何かに取り組んだ経験について教えてください。その中であなたはどのような役割を担いましたか？
    - チームの目標達成のために、あなたが貢献したことは何ですか？
    - チーム内で意見が対立した際、どのように対応しましたか？
    - チームのモチベーションを高めるために工夫したことはありますか？
    - あなたとは異なるタイプのメンバーと、どのように協力しましたか？
    - リーダーとフォロワー、どちらの役割が得意ですか？その理由も教えてください。
    - あなたの周りからは、どのような人だと言われることが多いですか？
    - 年上（もしくは年下）のメンバーと協力して何かを成し遂げた経験はありますか？
  - 志望動機
    - 弊社を志望している理由を教えてください
    - この業界を志望している理由を教えてください
    - 就活の軸を教えてください
    - 企業選びにおいて、最も重視しているポイントは何ですか？
    - 当社の企業理念について、共感できる部分があれば教えてください。
    - 当社の事業内容について、どのような印象をお持ちですか？
    - 当社のサービスや商品について、改善できる点があれば教えてください。
    - 入社したら、当社のどのような点に貢献できると思いますか？
  - 自己PR
    - あなたの強み（長所）を教えてください。
    - これまでの経験で、あなたの強みが発揮されたエピソードを教えてください。
    - その強みを当社でどのように活かせるとお考えですか？
    - あなたの弱み（短所）は何ですか？
    - その弱みを克服するために何か取り組んでいることはありますか？
    - あなたの弱みは、チームで働く上でどのような影響があると思いますか？
    - これまでの人生で、最も「自分らしい」と感じたエピソードを教えてください。
  - 仕事観・価値観・将来像
    - どのような人と一緒に働きたいですか？
    - 入社後、どのような仕事に挑戦してみたいですか？
    - 仕事を通じて成し遂げたいことは何ですか？
    - 5年後、10年後、どのようなキャリアを歩んでいたいですか？
  - ストレス耐性
    - プレッシャーを感じる状況はどのような時ですか？また、それをどのように乗り越えますか？
    - 意見の合わない人と、どのように仕事を進めていきますか？
    - 忙しい時期が続く時、どのように体調やモチベーションを管理しますか？
    - 気分転換やリフレッシュのために、日頃から行っていることはありますか？
  - エンジニア向けの質問
    - 新しいプログラミング言語や技術を学ぶ際、あなたはどのような方法で習得しますか？
    - あなたがこれまで作成した制作物（ポートフォリオ）について、一番工夫した点や苦労した点を教えてください。
    - 今，注目している技術はありますか？また，あなたならその技術をどのように使いますか？
    - チームでの開発経験があれば、その際の役割や貢献について教えてください。
    - 技術的な壁にぶつかった時、どのように情報を収集し、解決を図りますか？
- このとき，先に生成したスコアの理由，就活生の基本情報，企業の基本情報も参考にする
- それぞれの大項目ごとにmarkdownファイルを作る

### ユーザーとのインタラクション

- ユーザーが質問できるのは10分
- 10分経過後，質問を打ち切って，スコアをつけさせる
- そのスコアとあらかじめ計算したスコアとのズレを計算し，それにマイナスをかけたものをユーザーの基本成績とする
- 基本成績が平均50，標準偏差10になるようにいい感じに調整してユーザーに提示する
- フィードバック（もっとこういう質問をすればよかったなど）をユーザーに提示する
